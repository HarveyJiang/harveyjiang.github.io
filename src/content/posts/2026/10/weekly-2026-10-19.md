## 核心工作要点

### 自检 + 自愈闭环上线
新增两个 no_agent 定时任务：`hermes-selfcheck`（每日 08:30）做 8 项只读检查——cron 心跳、env 完整性、任务与基线比对、三机磁盘、dws 登录态、24h 失败统计；`hermes-autofix`（08:40）按白名单执行可恢复修复（`journalctl --vacuum-size=100M`、过期 cron 归档清理、dangling 镜像清理），所有动作写入 `autofix.log` 留痕，白名单外一律只报告不动手。
- **可复用经验**：配置漂移的根治是建立唯一事实源 `baseline.json`（env 变量、cron 任务、脚本路径、阈值），自检每日对比报告偏差；自愈不等于乱修，白名单才是关键。

### 事件驱动闭环打通
磁盘 ≥90% 时自检自动升级：HMAC-SHA256 签名 POST 到 `disk-alert` webhook 订阅（事件走 body `type` 字段路由），触发 Agent 对目标服务器做只读诊断（du/df 定位大文件、输出清理建议），报告推送钉钉。LLM 仅在严重异常时消耗，日常零成本。
- **可复用经验**：事件订阅的调试要点是先验证签名认证（`X-Hub-Signature-256`），再确认事件字段名——`{"event": ...}` 会被网关忽略，`{"type": ...}` 才能路由。

### 通知体系三轮打磨
`morning-briefing.sh` 从磁盘状态升级为服务器状态：安全评分（磁盘≥80 扣 15、内存≥85 扣 10、SSH 爆破分级扣分）、异地登录检测（`last -i` + 完整 IPv4 正则防误报）、钉钉待办接入（`dws todo task list`，按到期日分流）。另定位并关闭 `cron.wrap_response`，去除「Cronjob Response」英文包装，提醒原样投递。

### dws（钉钉 CLI）接入与设备授权
`dws auth login` 走设备授权流（后台进程保活避免轮询超时），登录后晨报读取钉钉待办、周报流程预留数据源，命令软链进 PATH。

### 发布链路重建与 creator profile 治理
博客仓库原路径失效，从 GitHub 重新克隆到 `/opt/data/projects/harveyjiang.github.io`；weekly-summary 改为 `git push origin master` + GitHub Actions 自动构建。核实各 profile 实际模型：creator/translate 均走 Cloudflare Workers AI（Gemma-4-26B / Qwen3-30B-A3B），修正过时记忆；发布环节强制 creator profile，禁止自动回退。
